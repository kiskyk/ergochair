# ErgoChair

身長と座位写真から、自分に合う椅子の座面高と机面高を算出するWebアプリ。
算出した範囲に収まる椅子を楽天市場から探して並べる。

**デモ: https://ergochair.pages.dev** （入力は身長だけでよく、そのまま試せる）

## 解こうとした問題

椅子が体に合うかどうかは座面高でほぼ決まるが、通販サイトの絞り込み条件に座面高が用意されていないことが多い。
座面高は商品説明の文章に埋もれていて、一件ずつ読まないと分からない。

そこで身長から適正な座面高を計算し、商品名と説明文から座面高を正規表現で抽出して、範囲が重なる商品だけを表示する。

## 動作例

身長172cmを入力すると、推奨座面高43cm（許容41〜44cm）、推奨机面高74.5cm、差尺31.5cmを算出する。
この範囲に対応する椅子が楽天市場から10件抽出される。

座位の横向き写真を追加すると、MediaPipe Pose Landmarkerがブラウザ内で骨格を検出し、膝とかかとの3D座標から下腿長を実測して精度を上げる。
写真は外部に送信されない。

## 設計上の判断

**費用ゼロで運用する**：静的サイトとサーバーレス関数だけで構成し、Cloudflare Pagesの無料枠に収めた。
データベースを持たず、状態はすべてブラウザ内で完結する。

**APIキーをブラウザに渡さない**：ブラウザは常に相対パス `/api/rakuten` を呼ぶ。
本番ではCloudflare Pages Function、ローカルでは `serve.py` が同じパスを受け、サーバー側の環境変数からキーを付与して楽天APIへ中継する。
キーがサーバーの外へ出ないため、リポジトリを公開してもキーは漏れない。

**推定に失敗しても止まらない**：写真がない場合、骨格を検出できない場合、下腿長と身長の比が0.20〜0.32の範囲を外れた場合の3通りで、身長ベースの数式モデルへ自動的に切り替える。
どの経路を通ったかは画面に表示するため、利用者は数値の由来を判断できる。

**計算ロジックを純関数に隔離する**：`calc.js` はDOMにもネットワークにも触れない。
ブラウザを起動せず `node --test` だけでテストできる。

## 算出式

人間工学の一般式を用いる。

- 下腿高 ≒ 身長 × 0.25（写真がないときの推定）
- 座面高 = 下腿高（かかとが床に着く高さ。許容範囲は −2cm から +1cm）
- 座高 ≒ 身長 × 0.55
- 差尺[^1] = 座高 ÷ 3
- 机面高 = 座面高 + 差尺

許容範囲を下側に広く取っているのは、座面が高すぎると足が浮いて太ももが圧迫されるためである。

[^1]: 座面から机上までの高さの差を指す日本の人間工学用語。

## 構成

| ファイル | 役割 |
|---|---|
| `index.html` | UI、MediaPipeによる姿勢解析、結果の描画 |
| `calc.js` | 計算ロジック（純関数、ESモジュール） |
| `calc.test.mjs` | `node --test` による単体テスト |
| `functions/api/rakuten.js` | 本番の楽天API中継（Cloudflare Pages Function） |
| `serve.py` | ローカル開発用の静的配信とAPI中継 |

## ローカルでの実行

```
cp .env.example .env   # 初回のみ。楽天APIキーを記入
python serve.py        # このフォルダで実行
# → http://127.0.0.1:8080 を開く
```

楽天APIは許可サイトを登録制で制限しているため、ローカル実行では商品検索が失敗することがある。
その場合も高さの算出は動作する。

## テスト

```
node --test
```
